# Lixyte — Design System

Rules for every page in `frontend/`. **Read this before writing or changing any UI**, and update it in the same change when you add a new pattern. Status tags: **[in use]** exists in code today, **[planned]** agreed but not built yet. If code and this file disagree, fix one of them — don't leave both. Last checked against `main` after merging PR #15 (`kzwnjuy`) and `Pek` (2026-11-17). Pages still to design are listed in `docs/TASKS.md`.

## 1. Principles
- **Dark-first, HUD/x-ray look.** Black canvas, thin light lines, glowing accents. The reference is the spectral lily landing page. (Light/Dark switching was discussed earlier and is deferred; build dark only until it is requested.)
- **One system.** Reuse the tokens and components below. No one-off colors, font sizes or radii.
- **Content over chrome.** Thin borders, low-contrast panels, accent color only for the one thing that matters on screen.
- **No new dependencies** for UI. Stack is Next.js 15 (App Router), React 19, Tailwind 3, `lucide-react`, `three`.

## 2. Color
Dark surfaces use black with white at low opacity. Accents come from the HUD palette of the lily scene.

| Token | Value | Use |
|---|---|---|
| bg | `#000000` | page background (`globals.css`) [in use] |
| nav | `bg-black/90` + `backdrop-blur` | Navbar [in use] |
| text | `text-white` | primary text, active links [in use] |
| text-muted | `text-white/65` | inactive links, secondary text [in use] |
| text-faint | `text-white/40` | placeholders, hints [in use] |
| line | `border-white/10` | dividers, navbar border [in use] |
| line-strong | `border-white/15` → `border-white/50` on focus | inputs [in use] |
| fill-subtle | `bg-white/5` | inputs, quiet panels [in use] |
| hud | `#8fd3ff` (`text-hud`) | HUD accent, glow, focus, micro labels [in use] |
| violet | `#b892ff` (`via-violet`) | gradient accent [in use] |
| amber | `#ffb070` (`to-amber`) | highlight, tab markers [in use] |
| panel | `rgba(4,8,18,.66)` | HUD cards [in use] |

Rules:
- Gradient accent (headlines only): `hud → violet → amber`, 92deg.
- Never use pure-color text on pure-color backgrounds; keep contrast ≥ 4.5:1 for body text (WCAG 2.2 AA; it has no exception for small or uppercase text).
- Contrast on the `#000` background (calculated, not measured in a browser): `text-white/65` ≈ 8.6:1 passes. `text-white/40` ≈ 3.7:1 does **not** pass 4.5:1, so use it only for placeholders and decoration, never for text people must read (for example "Image" on a card placeholder, the footer copyright line). UI borders and focus rings need ≥ 3:1: `border-white/10` is decoration only, so inputs and focus states keep `white/15` → `white/50`.
- Status: success = green, error = red, both used sparingly and always with an icon or label (never color alone).
- `tailwind.config.ts` still has a legacy `brand` pink (`#ff4d6d`). It is **not** part of this system and unused; remove it or replace it when tokens are added to the config.

## 3. Typography
| Role | Font | Notes |
|---|---|---|
| Body / UI | **Chakra Petch** 400/500/600 | loaded in `app/layout.tsx` via `next/font/google`, applied on `<body>` [in use] |
| Display headlines | **Michroma** (`font-display`) | wide, uppercase, `leading-[1.02]` [in use] |
| Data / labels / numbers | **Share Tech Mono** (`font-mono`) | micro labels `text-[11px]`, `tracking-[0.16em]`, uppercase, tabular numbers [in use] |

Both are loaded in `app/layout.tsx` as CSS variables (`--font-display`, `--font-mono`) and mapped in `tailwind.config.ts`. Changing `tailwind.config.ts` requires restarting `npm run dev`.

Sizes (Tailwind): body `text-[15px]`/`text-sm`; nav links `text-[15px]`; small labels `text-[10–11px]` uppercase with wide tracking; page hero `clamp(30px, 4.6vw, 66px)`. Weights: 400 body, 500 emphasis, 600 brand/logo. Don't introduce other families.

## 4. Spacing & layout
- Scale: Tailwind's 4px steps. Prefer `1, 2, 3, 4, 5, 6, 8, 12, 16`. No arbitrary pixel values unless matching a rule here.
- Page gutter: `px-4` (mobile), `md:px-6`. Content max width `max-w-[1400px]`, centered.
- Navbar: fixed, `h-16` (64px), `z-50`. Page content that is not full-screen needs `pt-16` so it isn't hidden under it.
- Breakpoint for layout switches: `md` (768px). Design mobile first; verify at 375px.
- Gaps: between nav items `gap-5`, between controls `gap-3`.
- Radius: `rounded-lg` (8px) for buttons and inputs. HUD cards use clipped corners instead (see Cards).

## 5. Buttons
All buttons: `h-9`-ish, `rounded-lg`, `text-[15px]`, `transition-colors`, visible keyboard focus (`focus-visible` outline, never remove without replacement).

| Variant | Classes | Use |
|---|---|---|
| Primary | `bg-white text-black font-medium px-3.5 py-1.5 hover:bg-white/85` | the one main action (e.g. Log in) [in use] |
| Text / ghost | `text-white/65 hover:text-white` | secondary actions (e.g. Log in) [in use] |
| Icon | `h-9 w-9 grid place-items-center text-white/80 hover:text-white`, needs `aria-label` | search toggle [in use] |
| Outline (HUD) | `border border-white text-white hover:bg-white hover:text-black`, uppercase, tracking `.18em`, `text-[10.5px]` | HUD actions like "Explore gallery" and "See how it works" [in use] |

One primary button per view. Destructive actions need confirmation and never use the primary style.

## 6. Inputs
`h-9 rounded-lg border border-white/15 bg-white/5 px-3 text-sm text-white placeholder:text-white/40 focus:border-white/50 focus:outline-none`. With a leading icon: `pl-9` and a `h-4 w-4 text-white/50` icon. Always has a `label` or `aria-label`. [in use: navbar search]

**Native `<select>`:** use a solid fill (`bg-black`), never a translucent one like `bg-white/5` (the popup list inherits it and turns white with white text). `globals.css` sets `color-scheme: dark` on selects and a dark background with white text on `select option`, so every dropdown list stays readable. [in use: report popup, admin lists]

## 7. Cards
- **Model card** (gallery) [in use, `components/gallery/ModelCard.tsx`]: `bg-white/5`, `border border-white/10`, `rounded-lg`, poster on top (lazy-loaded; without `posterUrl` a flat `bg-white/[0.06]` placeholder with a lucide `Image` icon and the word "Image", `text-white/40`), title `text-sm font-medium`, creator `text-white/65`, badge for Free / price, like count. Hover: border → `white/30`. Same card is reused on the landing "Popular models" section.
- **HUD card** (landing/callouts only): panel fill `rgba(4,8,18,.66)`, 1px `rgba(143,211,255,.38)` border, clipped top-right and bottom-left corners (`clip-path: polygon(0 0, calc(100% - 16px) 0, 100% 16px, 100% 100%, 16px 100%, 0 calc(100% - 16px))`), small tab label above in uppercase. Don't use HUD cards for regular content pages.

## 8. Icons
- Library: **`lucide-react` only.** No emoji icons, no other icon packs, no inline one-off SVGs unless it's a logo or 3D-scene artwork.
- Sizes: `h-4 w-4` inside inputs/labels, `h-5 w-5` for standalone icon buttons. Default stroke width.
- Color follows text color (`currentColor`). Decorative icons get `aria-hidden`; icon-only buttons get `aria-label`.

## 9. UI patterns
- **Navigation:** Navbar on every page via `app/layout.tsx` **except the auth pages** (`/login`, `/forgot-password`), where `Navbar` and `Footer` render nothing (list in `lib/auth-paths.ts`; the admin area hides them too, see the Admin pattern below) and the page uses plain `py-16` instead of the navbar offset `pt-24`: left = logo, `Gallery`, `Docs`, `Creator` (→ `/creator`, the creator landing page), search; right = the language button (bordered `h-9`; icon only below `sm`, icon plus `EN` / `ไทย` from `sm`) and a single `Log in` button (it covers sign up too; `/login` decides; `ล็อกอิน` in Thai, short on purpose to fit a phone). Nav links are `whitespace-nowrap` so Thai words never break. Checked at 360 and 375px in both languages, signed out and signed in: fits; at 320px the right button is clipped by about 26px (English) so 320px is not supported. Active link = `text-white` + `aria-current="page"`. Below `md` the search collapses to an icon that opens a full-width row. [in use]
- **Search:** submitting (Enter) goes to `/gallery?q=...` (empty box → `/gallery`); no live dropdown. The gallery searches title, description, creator and tags. [in use]
- **Logged-in navigation** (`components/AccountMenu.tsx`, read from `lib/session.ts`): signed out = the white `Log in` button; signed in = a round `h-9 w-9` button with the person's initials and a `border-hud/50` ring (`aria-label="Account menu for <name>"`, `aria-expanded`). It opens a panel in the same style as the filter dropdown (`absolute right-0 top-full mt-2 w-56 rounded-lg border-white/15 bg-black/95 p-1`): name and email on top, then `Library` (`/me`), `Seller dashboard` (`/seller`, only when `is_seller`), `Creator profile`, `Settings` (`/settings`), `Report a problem` (opens the report popup) and `Log out`. For an admin the menu has only `Admin dashboard` (`/admin`) and `Log out` (no Library, Seller or Report items). Admins normally never see the public pages: `components/AdminOnlyRedirect.tsx` sends a signed-in admin to `/admin` from every page except `/embed/*`, so after logging in they land there. The one way out is the **View Website** button of the admin layout, which sets a per-tab flag (`lib/admin-view.ts`, `sessionStorage`) so the public site opens normally in that tab; opening any `/admin` page or logging out clears the flag. Admin tables show model titles as plain text, not links. `Log out` (clears the saved sign-in and goes to `/`). Items are `py-2` (32px tall). Closes on Escape (focus returns to the button), outside click and page change. The saved sign-in is read after mount and on every page change, so the button is invisible (same size as `Log in`) until then: no flicker, no layout shift. An expired or damaged saved sign-in counts as signed out. Hiding menu items is only convenience; every page and API must check the role again on the server. `/seller` does not exist yet (404). [in use]
- **Pixie cursor** (landing only, `components/PixieCursor.tsx`): a glowing orb (white core, hud→violet halo) with two tiny flickering wings and a sparkle trail (hud / violet / amber particles, max 140, additive blending). Drawn on a full-viewport `<canvas>` (`fixed inset-0 z-20 pointer-events-none`, below the Navbar's `z-50`). Mouse: chases the pointer with eased motion, wings face its direction, more sparkles while moving, hovers in a small loop after the mouse is still for 1.2s. Touch devices and before the first mouse move: flies around the flower. `prefers-reduced-motion`: one static pixie, no chase, no trail. Animated in `requestAnimationFrame` (no React re-renders). Replaced an earlier butterfly design. [in use]
- **Forms / auth page** (`app/login/page.tsx`, `components/auth/AuthForm.tsx`) [in use]: centred column `max-w-[420px]` on a black page with a soft hud/violet radial glow (`absolute inset-0 -z-10`, page `isolate`). Mono label → Michroma `h1` → lead text → card `rounded-lg border-white/10 bg-white/5 p-5 sm:p-6`. One email-first flow, no tabs: (1) **Email** (+ Continue with Google) → `checkEmail` (core-api `POST /api/auth/check-email`) → (2a) known email: **Welcome back**, password field + "Forgot password?" link → `login`, or (2b) new email: **Create account**, display name + password (min 8) → `register`. Success saves the token and goes on; there is no one-time-code step (the earlier design had one; it was dropped when login was connected). After step 1 the chosen email is shown in a bordered row with a "Change" button that returns to step 1. The "this email is registered" answer lets people probe for accounts, so it must be rate-limited server-side (not done yet, see `docs/ARCHITECTURE.md`). Form fields use `h-10` (taller than the navbar search's `h-9` for touch), visible `label` above (`text-sm text-white/65`), `rounded-lg border-white/15 bg-white/5`, focus `border-white/50`. Errors: `border-red-400/70` + `text-sm text-red-300` with an `AlertCircle` icon (never colour alone), linked with `aria-invalid` / `aria-describedby`. Validate on submit, then live. Password field has a show/hide icon button. One primary full-width button. A secondary "Continue with Google" button (outline style: `h-10 border-white/15 bg-white/5`, inline Google brand mark since lucide has none) sits above the form, separated by an "or" divider; UI only (not in the backend), it just shows the status line. ## 10. Working rules for Claude
1. Before UI work, read this file; reuse existing components (`components/Navbar.tsx`, `components/viewer/*`) before creating new ones.
2. Need a value that isn't here? Add it here first (with a tag), then use it. Don't hardcode ad-hoc colors/sizes in components.
3. Keep components small and in the folders named in the README (`components/gallery`, `components/viewer`, `components/playground`).
4. Verify visually in the browser at desktop and 375px before saying a UI change is done.
5. Don't run `next build` while `npm run dev` is running — they share `.next` and break the dev server. Use `npx tsc --noEmit` for type checks instead.
6. `/docs` exists now; don't change the Navbar link to it.
